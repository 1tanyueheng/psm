Enrol on acknowledgement, and put the PSM 2 title decision on the project page.

**The gap the last session found is closed.** Capacity is counted from
`student_enrolments`, and registration never created one, so a student who came
through Lampiran A held a supervision and consumed no supervisor slot. The
acknowledgement now enrols them in the same transaction as the pairing, which is
where the faculty actually decides the student holds a place in that part for
that term. `enrol()` returns an existing live row, so an admin who enrolled them
by hand first is not punished for it. Verified against the live database:
enrolments 0 -> 1, supervisor PSM 1 load 0 -> 1.

**The PSM 2 boundary is now a question, asked once.** A student opening their
PSM 2 project for the first time is shown a card on the project page: keep the
inherited title, or change it. Keeping is recorded rather than assumed
(`metadata.title_decision`), because without that answer the prompt either nags
on every visit or never appears. Three endpoints back it: a status read, a
decision write, and the existing title-change request that `change` now calls.
Verified over HTTP: status reports eligible/can_change true and decided false;
posting `keep` flips `decided` to true and clears the card.
