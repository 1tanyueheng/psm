sequenceDiagram
    autonumber
    actor User
    boundary LoginUI as Login screen<br/>(React SPA)
    control AuthController as AuthController<br/>(Laravel API)
    control LoginRequest as LoginRequest<br/>(validation)
    database DB as PostgreSQL
    control UserModel as User<br/>(model)
    control Audit as AuditLogger

    User->>LoginUI: Enters an email address and a password
    LoginUI->>LoginUI: Checks the form is filled in correctly
    LoginUI->>AuthController: Sends the login request
    AuthController->>LoginRequest: Checks the request and tidies the email
    LoginRequest-->>AuthController: Returns the email in a standard form

    AuthController->>DB: Queries the account by email
    DB-->>AuthController: Returns the account record, or nothing

    alt No account matches the email
        AuthController->>Audit: Records the failed attempt
        AuthController-->>LoginUI: Rejects the login, credentials do not match
    else The account is locked
        AuthController->>UserModel: Checks whether the account is locked
        UserModel-->>AuthController: Confirms the lock is still in force
        AuthController-->>LoginUI: Rejects the login, account locked until a time
    else The password is wrong
        AuthController->>UserModel: Compares the password with the stored one
        UserModel-->>AuthController: Reports no match
        AuthController->>UserModel: Counts the failed attempt and locks if needed
        AuthController->>Audit: Records the failed attempt
        AuthController-->>LoginUI: Rejects the login, credentials do not match
    else The account is suspended or inactive
        AuthController->>UserModel: Checks the account status
        UserModel-->>AuthController: Reports the account is not active
        AuthController-->>LoginUI: Rejects the login and states the reason
    else The credentials are correct
        opt The user asks for a clean session
            AuthController->>DB: Removes every previous login token
        end
        AuthController->>DB: Stores a new login token
        DB-->>AuthController: Returns the token
        AuthController->>DB: Updates the sign in time and clears the failures
        AuthController->>Audit: Records the successful sign in
        AuthController-->>LoginUI: Confirms the login and returns the user
    end

    LoginUI->>LoginUI: Keeps the token and the signed in user
    LoginUI-->>User: Redirects to the dashboard for their role

    Note over LoginUI,DB: Each later request carries the token,<br/>so the system knows who is asking<br/>before the page is opened.
